# ADR 011 Independent application connectors for ITEROP and the dataset catalog

Status: Adopted and implemented (NOVA-003, 7 October 2026).

## Context

Olivier asked for Business Process (ITEROP) and Datasets Governance to come before AURA. These products differ from the engineering-item service, and may differ from each other, in their origin, authentication (ITEROP access keys, or the API Gateway with the PFI role), entitlement and schemas. The existing gateway assumes one origin, one credential and an engineering-item schema.

## Decision

Add a small provider abstraction (`server/apps/`). Each application has:

- an independent configuration namespace;
- a contract schema bound to that application, which rejects other applications' operations and foreign documentation hosts;
- a semantic operation registry with field allowlists and required fields;
- a synthetic adapter;
- a connection probe.

The operator, not the prompt, selects the application. The shared bounded GET transport is extracted to `server/http.ts`, and the engineering gateway reuses it unchanged.

## Consequences

- A credential or contract for one application can never be used for another.
- Adding a documented operation means adding a contract binding, and a registry entry only if the semantic intent is new.
- POST-based reads, pagination traversal and token exchange remain unimplemented until a reviewed contract requires them.
- Live results remain unclaimed until a private proof run.

## Verification criteria

`tests/apps.test.ts` checks:

- isolation and namespaced configuration;
- that checked-in templates fail admission;
- rejection of writes, foreign applications, foreign documentation and path traversal;
- field projection without secrets;
- denial without retry;
- unknown coverage;
- intent routing.

`tests/e2e/applications.spec.ts` checks the UI journeys, accessibility and keyboard use.
