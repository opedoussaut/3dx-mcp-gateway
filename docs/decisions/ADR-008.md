# ADR 008 AURA as a configured black box

Status: Adopted in blueprint v0.1; implementation pending.

Date: 5 October 2026.

## Context

AURA internals and tenant capabilities may not be observable, making architecture-only causal claims unsound.

## Decision

Freeze representative missions before testing. Compare same-user common-access conditions where verifiable, and separate deployment-capability results otherwise. Record AURA release/competency and use its supported user interface unless a public test API is verified. Unknown metrics remain NOT_OBSERVABLE.

## Consequences

No guessed model costs, token counts or hidden tool activity. Access parity does not isolate undisclosed model/retrieval differences. Within-NOVA ablations provide stronger evidence about NOVA design components. Product claims are not measured outcomes.

## Verification criteria

- Require access/permission/corpus parity records for common-access pairs.
- Report every run and protocol deviation, including failures.
- Keep evaluator answer keys out of system inputs and reviewer identity blind where feasible.

## Alternative considered

Selecting only missions where AURA is expected to fail, or estimating its invisible internals; rejected.
