# ADR 004 Policy constrained cognitive routing

Status: Adopted in blueprint v0.1; implementation pending.

Date: 5 October 2026.

## Context

Not every engineering mission needs an LLM, and a learned router can be wrong.

## Decision

Apply deterministic eligibility filters before route selection. Prefer deterministic execution and introduce decision models only after held-out calibration. Permit abstention. Learned scores cannot approve writes, enable APIs, change security context or authorize data egress. Skip unnecessary intermediate levels.

## Consequences

Routing policies require versioning and measurement. Raw confidence is not a correctness probability. Unknown tasks may need conservative escalation, clarification or stopping. A 9B decision model and a tiny classifier are separate cost classes.

## Verification criteria

- Test denied tool/provider choices even when the learned router recommends them.
- Record held-out error, abstention, coverage and under-escalation.
- Compare total cost and quality against a fixed-provider baseline.

## Alternative considered

Always use a frontier model, or allow a learned model to be the authorization engine; both rejected.
