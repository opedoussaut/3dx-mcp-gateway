# ADR 001 Public architecture and private runtime

Status: Adopted in blueprint v0.1; implementation pending.

Date: 5 October 2026.

## Context

The architecture must be publishable while tenant access and engineering evidence remain private.

## Decision

Maintain separate public source, private runtime and external-provider trust zones. Publish original specifications and synthetic fixtures. Keep tenant configuration, credentials, identity maps, evidence, screenshots and operational traces outside the repository. Corporate model egress defaults to denied until an approved provider and data policy are configured.

## Consequences

A public demo cannot serve as the corporate runtime. Reproduction uses synthetic inputs; live trials require an independently configured private environment. An export requires both sensitive-data screening and explicit publication rights.

## Verification criteria

- Verify repository and built assets contain no private runtime files.
- Insert synthetic secret canaries into test failures and assert no log, prompt or export contains them.
- Verify corporate data cannot reach an unapproved model destination.

## Alternative considered

Single public-hosted UI/backend connected directly to a corporate tenant; rejected because it joins trust zones unnecessarily.
