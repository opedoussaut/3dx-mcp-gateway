# ADR 002 Semantic MCP tools only

Status: Adopted in blueprint v0.1; implementation pending.

Date: 5 October 2026.

## Context

An unconstrained REST executor would allow models to select unsupported endpoints, hosts and operations.

## Decision

Expose typed semantic tools from an allowlisted registry. Only the gateway constructs approved HTTP requests and supplies platform authentication. Arguments use bounded values and gateway-local handles. Tool discovery reflects configured capability admission rather than network probing.

## Consequences

New capabilities require registry review and adapter work. This intentionally limits breadth. Output schemas and MCP risk annotations are hints for interoperability; gateway enforcement remains authoritative.

## Verification criteria

- Reject arbitrary URL, method, header and host arguments.
- Reject forged handles that cross principal, tenant or context boundaries.
- Verify all API requests map to admitted operations and bounded fan-out.

## Alternative considered

Generic execute_rest tool; rejected because semantic and security constraints would be delegated to model behavior.
